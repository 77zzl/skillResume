# skill-resume

一个面向 GPT/Codex Agent 的简历生成 Skill：把候选人的真实材料、目标岗位 JD 和当前招聘市场信号，编译成岗位匹配、ATS 友好、视觉统一的三套简历，并同时输出可编辑 Word 与 PDF。

本次版本新增两项能力：

1. 中国国内招聘平台研究：针对中国大陆岗位，自动把目标公司官网、BOSS直聘、猎聘、智联招聘、前程无忧、拉勾、牛客、实习僧、应届生求职网、国聘和国家大学生就业服务平台纳入搜索路由，并记录来源、日期、岗位信号和平台限制。
2. 非阻塞式必要信息收集：GPT 会一次性询问姓名、联系方式、教育、经历、项目成果等缺失信息，但不会等待用户回答才生成。缺失信息会进入审计清单，后续补充后可以继续修订。
3. 三套同文案交付：ATS、Modern、Research 三种风格必须使用同一份编译文本，并各自输出 PDF 和可编辑 DOCX。
4. 编辑后转换：再次上传编辑后的 DOCX 并提出“转成 PDF”时，直接以该 DOCX 为源文件转换，不从旧简历清单重写，避免覆盖用户的手工修改。
5. 按城市推荐企业：根据简历、目标岗位和用户填写的期望就业城市，默认联网寻找并推荐 20 家不重复的匹配企业；中国大陆城市走中文招聘平台，海外城市走当地/国际招聘平台，港澳台单独标记为区域市场。
6. 分栏与图片保留：Modern 和 Research 恢复左窄右宽的双栏排版，所有风格都建立明确的姓名、职业标题、区块标题、条目标题和正文层级；用户提供的头像和二维码会被嵌入 HTML、Word 和 PDF，不再因为重新生成而丢失。

## JD 是什么

JD 是 `Job Description` 的缩写，中文通常叫“职位描述”“岗位描述”或“岗位说明”。它是招聘方写的岗位需求，通常包含岗位职责、必须技能、加分技能、学历/经验要求、工作地点、语言要求和预期产出。

对本 Skill 来说，JD 不是一段普通文本，而是“目标函数”：它决定哪些候选人证据应优先展示、哪些关键词需要保留、哪些项目应该排在前面，以及应该采用哪种简历版本和排版。

| 最终质量检查 | `scripts/validate_resume_package.py`、`references/output-contract.md` | 检查占位符、HTML 语义、证据引用、研究记录和 PDF 页数 |

## 非阻塞式信息收集是怎样工作的

GPT 每次开始时先检查材料中是否包含以下信息：

- 目标岗位、公司、城市和完整 JD；
- 姓名、邮箱、电话和所在城市；
- 学校、学历、专业和毕业时间；
- 工作/实习/项目的组织、角色、时间和个人负责部分；
- 可验证的成果、规模、交付物、论文、奖项或部署信息；
- 使用过的技术、工具和方法；
- 作品集、GitHub、论文或证书链接。

它会把缺失内容整理成一条中文补充清单，然后继续生成：

- 缺姓名：草稿可以使用“候选人”或省略姓名；
- 缺联系方式：简历中省略联系方式，并在提交前提醒；
- 缺 JD：生成通用岗位版本，但标记为非 JD 定制版本；
- 缺日期：只使用已确认日期，不能猜测；
- 缺数字：使用事实、方法、范围或交付物，不编造百分比；
- 缺教育经历：省略教育模块；
- 缺成果：保留方法型描述，并列出可以补充的验证问题。

所以“询问用户”与“生成简历”是两个并行动作，而不是先问完才能继续。完整字段约束见 `references/required-information.md`。

## 中国国内联网搜索策略

国内平台只用于发现岗位市场信号，不能证明候选人具备某项能力。默认优先搜索目标公司官网的原始 JD，再根据岗位类型选择平台：

| 岗位场景 | 重点搜索来源 |
| --- | --- |
| 互联网技术、产品、运营 | 目标公司官网 + BOSS直聘/拉勾/牛客 + 一个综合平台 |
| 校招、实习 | 目标公司校招页 + 牛客/实习僧/应届生求职网 + 国家大学生就业服务平台 |
| 国企、央企、公共招聘 | 目标单位官网 + 国聘 + 国家大学生就业服务平台或当地公共就业平台 |
| 中高端专业岗位 | 目标公司官网 + 猎聘 + 一个综合平台 |
| 综合社招 | 目标公司官网 + 智联招聘/前程无忧/BOSS直聘中的两个来源 |

搜索时会保留：

- 原始岗位关键词；
- 任职要求和硬性筛选条件；
- 预期产出和业务场景；
- 学历、经验、城市、到岗等岗位条件；
- 多个职位中重复出现的要求；
- 搜索日期、来源链接和平台访问限制。

如果平台需要登录、页面不可访问、内容明显过期或多个页面只是重复转载，Skill 会记录限制并换用可核验来源，不会假装完成了平台调查。

## 企业推荐模式

你可以只使用企业推荐功能，不必先生成简历。它会读取你上传的简历和目标岗位信息，重点使用期望就业城市来决定搜索范围：

- 中国大陆城市：使用中文查询，优先企业官网，并结合 BOSS直聘、猎聘、智联招聘、前程无忧、拉勾、牛客、实习僧、应届生求职网、国聘和国家大学生就业服务平台等国内来源；
- 海外城市：使用英语或当地常用语言，优先企业官网，并结合 LinkedIn Jobs、Indeed、Glassdoor、Wellfound、当地公共就业平台和专业协会；
- 香港、澳门、台湾：作为 `港澳台/区域` 单独处理，不把它们默认为中国大陆或海外；
- 多个城市：分城市检索并在每一家公司旁标明地点；
- 没有填写城市：先提醒补充，但不阻塞简历生成；推荐只能标记为“待确定城市”或“潜在适配”，不能声称已验证某城市正在招聘。

默认推荐 20 家。用户指定数量时按用户数量执行；如果公开岗位不足 20 家，宁可返回较少结果，也不重复公司凑数。每家公司应包含：匹配岗位、城市、状态、匹配原因、对应简历证据、主要缺口、投递链接、来源类型和检索日期。`open` 表示检索时有公开岗位，`recent` 表示有近期招聘信号，`potential_fit` 表示企业与简历较匹配但没有核验到当前开放岗位。

推荐分数只用于排序，不代表录用概率。正式投递前应重新打开链接，因为招聘页面可能关闭、过期或发生地点变化。

## 文件分别是什么、重要性如何

可以把整个 Skill 看成一个小型软件项目：

- `SKILL.md` 是“总控制器”。它定义什么时候启用、先做什么、什么时候询问用户、如何联网以及哪些事情绝对不能做。对 Agent 的行为最重要。
- `agents/openai.yaml` 是“界面配置”。它提供显示名称、简介、默认示例提示词和品牌色，不负责简历分析逻辑。
- `references/` 是“专业知识库”。其中 `required-information.md` 负责信息收集，`evidence-ledger.md` 负责真实性，`jd-rolefit.md` 负责岗位匹配，`web-research.md` 负责国内/国际联网研究，`output-contract.md` 负责交付标准。
- `scripts/` 是“确定性执行层”。模型适合做语义判断，但文件扫描、模板填充、Word 生成、Word 转 PDF、占位符检查和页数检查交给脚本更稳定。
- `assets/` 是“输出素材层”。三个 HTML 模板只负责视觉差异，简历文本来自同一个编译清单。
- `README.md` 是“给人看的说明书”，帮助使用者、维护者和面试官理解项目，不是 Agent 的主要行为来源。

简单记忆：`SKILL.md` 决定流程，`references/` 决定判断，`scripts/` 保证执行，`assets/` 负责外观，`openai.yaml` 负责界面展示。

## 为什么之前没有分栏，以及现在如何约束

之前的 HTML 模板已经有分栏，但 Word 生成脚本只是顺序写入普通段落，因此最终以 Word 为源转换 PDF 时，分栏信息没有被带过去。现在已经把排版约束落实到生成器：

- `ats`：单栏，作为 ATS 和网申安全版本；
- `modern`：左栏放目标方向、核心能力、教育经历，右栏放个人概览、工作经历、项目经历；
- `research`：同样使用双栏，但使用深蓝色、技术/学术风格和更强的项目层级。

三种风格仍然从同一个 manifest 生成。双栏只改变布局，不改变文字和事实顺序。姓名字号最大，职业标题次之，区块标题再次之，条目标题大于日期/地点和正文；每个区块标题还有主题色、底线或色块等视觉信号。完整约束见 `references/layout-and-assets.md`。

## 头像、二维码和其他图片

只要用户提供了头像、证件照或二维码，Skill 默认保留，不会自动删除、替换或裁剪。推荐使用以下字段：

```json
{
  "images": {
    "avatar": {"path": "C:/path/avatar.jpg", "alt": "候选人头像"},
    "qr_code": {"path": "C:/path/wechat-qr.png", "alt": "微信二维码", "label": "微信联系"}
  }
}
```

HTML 会把本地图片转换为 data URI，Word 会将图片写入 DOCX 的 `word/media/`，再由 Word/PDF 转换链路带入 PDF。若图片路径不可访问或格式不支持，Skill 会继续生成文字简历，同时在审计中说明图片未能嵌入；不会用随机图片或占位框冒充原图。

## 最终交付结构

一次正常生成应至少得到以下六个文件：

```text
resume-ats.docx       可编辑 Word
resume-ats.pdf        ATS 风格 PDF
resume-modern.docx    可编辑 Word
resume-modern.pdf     Modern 风格 PDF
resume-research.docx  可编辑 Word
resume-research.pdf   Research 风格 PDF
```

三种风格的事实和文字必须完全一致，只允许改变颜色、字体、间距、层级和视觉分组。每套 Word 都应是真正可编辑的普通文字，而不是把整页简历作为图片插入。

## 再次调用时将编辑后的 Word 转成 PDF

上传之前生成并手工编辑过的 `.docx`，然后发送：

```text
这是我编辑后的 skill-resume Word 简历，请不要改写内容，直接将这个 Word 转成 PDF。
保留我在 Word 中做过的文字、顺序、字体、间距和排版修改，并输出同名 PDF。
```

Skill 应进入 `edited_docx_to_pdf` 模式：不再联网研究、不再根据旧 JSON 清单重新生成、不覆盖用户修改。若当前 GPT 环境不提供 DOCX 转 PDF 的文档转换能力，应明确提示用户在 Word 中选择“另存为 PDF”，不能把 `.docx` 文件简单改名为 `.pdf`。

## 在 ChatGPT 的自定义 GPT 中使用

这是给中文 ChatGPT 用户的推荐映射：

| GPT 配置区域 | 放入内容 |
| --- | --- |
| Instructions / 指令 / 说明 | `SKILL.md` 的行为规则，或直接粘贴其中的正文 |
| Knowledge / 知识 / 知识文件 | `references/evidence-ledger.md`、`jd-rolefit.md`、`web-research.md`、`required-information.md`、`layout-and-assets.md`、`output-contract.md` |
| 可选参考资料 | `assets/` 下三个 HTML 模板 |
| Capabilities / 能力 | 打开“联网搜索”；如需生成文件，打开“代码解释器与数据分析” |
| Actions / Apps | 第一版不需要；只有接入招聘网站、ATS 或云盘时才配置 |

个人简历、项目说明和证书材料建议在每次对话中临时上传，不要把手机号、身份证号等隐私信息永久放入 Knowledge。联网搜索时也不能把这些隐私放进查询词。

### 推荐使用流程

第一轮上传个人材料和目标 JD，然后发送：

```text
请先不要直接生成最终简历。

请根据我上传的材料和目标岗位 JD：
1. 用中文解析岗位职责、硬性要求、加分项和关键词；
2. 针对中国大陆求职市场联网搜索目标公司官网及相关国内招聘平台；
3. 建立候选人证据账本；
4. 分析我与岗位的强匹配、可迁移匹配和缺口；
5. 列出缺失或需要确认的信息，但不要等待我的回答；
6. 继续用已有事实生成一版简历草稿。

所有联网来源附上链接、来源类型和检索日期，不得虚构任何经历或数字。
```

如果你希望根据简历寻找企业，可以在中文 ChatGPT 中发送：

```text
请根据我上传的简历、目标岗位和期望就业城市，推荐 20 家适合我的企业。
如果期望城市在中国大陆，请使用国内中文招聘网站和企业官网；如果在海外，请使用对应国家/地区的招聘网站和企业官网；港澳台请单独标记市场。
每家公司请给出：公司名称、城市、最匹配的岗位、当前状态、匹配原因、对应的简历证据、主要缺口、投递链接、来源类型和检索日期。
不要推荐重复公司；如果公开岗位不足 20 家，请返回实际找到的数量并解释原因。不要自动投递。
```

确认分析后，再发送：

```text
请根据刚才的分析生成最终中文简历。

要求：
1. 只使用有证据支持的事实；
2. 根据 JD 调整摘要、技能、项目和经历顺序；
3. 同一份文本生成 ATS、Modern、Research 三种排版；
4. 如果我提供了头像或二维码，请在三种风格中都保留，并保持原始比例；
5. 推荐最适合中国大陆当前投递场景的一种；
6. 输出岗位研究摘要、完整简历、缺失信息清单和最终审计；
7. 必须输出 ATS、Modern、Research 三种风格；每种风格都输出可编辑 DOCX 和 PDF。
8. 如果当前环境不支持 DOCX 转 PDF，请明确说明限制，不要伪造 PDF 或直接修改文件扩展名。
```

## 输出的基本要求

- 真实性优先：不编造数字、雇主、职责、技能和成果。
- 国内适配：中文 JD 默认执行中国大陆平台研究，不再只参考海外招聘平台。
- 企业发现：根据期望就业城市选择中文国内或海外招聘信息源，默认推荐 20 家去重企业，并区分当前岗位、近期信号和潜在适配。
- 低人工参与：缺失信息会被询问，但不会阻塞草稿生成。
- 岗位驱动：同一套材料按不同岗位自动选择和排序，必要时生成不超过三个岗位版本。
- 美观且可解析：视觉层级服务于阅读，关键信息仍然是普通文本。
- 可编辑可回转：Word 文件保留普通文本和可编辑结构，编辑后可以再次转成 PDF。
- 可解释：审计报告能回答“为什么选这段经历”“这句话来自哪里”“还缺什么信息”。
