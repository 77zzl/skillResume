# skill-resume

Turn source materials and a target job description into a small, evidence-backed resume package. Treat the process as a compilation pipeline: source facts become a structured evidence ledger, the JD becomes a role-demand matrix, and the final resume is a deliberately selected and rendered view of that data.

## Default behavior

- Prefer automatic execution. Ask the user only for missing facts that can change truthfulness or materially change the target, such as an unclear metric, date, ownership claim, or required job family.
- Start with one grouped, non-blocking intake pass. Ask for absent resume essentials and high-value evidence, then continue immediately with the information already available. Read [references/required-information.md](references/required-information.md). Missing answers must never prevent a truthful draft; record them in `audit.intake` and revise later if the user responds.
- Never infer a credential, employer, project result, technology proficiency, or metric from a keyword alone. Put unresolved claims in `needs_confirmation` and exclude them from the resume.
- Reuse all relevant source material, but select content by the target role. Produce one version when the role is coherent; produce at most three variants only when role families have materially different evidence or keywords.
- Keep the main resume to one page unless the user explicitly requests otherwise. Make the output ATS-readable: real text, ordinary headings, standard section order, no image-only text, no tables used as layout, and no decorative elements that hide keywords.
- Translate internal module names and research jargon into recognizable capability categories. Preserve the technical method, but explain why it matters to the target role.
- Quantify only with source-backed numbers. When no number exists, use a verifiable artifact, scope, dataset, deployment context, or ownership statement instead of fabricating impact.
- When a target role or JD is available, perform current web research by default. Use it to identify role-specific hiring signals, terminology, and visual conventions; never treat web guidance as evidence that the candidate possesses a skill.
- When the target is in mainland China, the JD is in Chinese, or the intended market is Chinese-speaking, run a China-market research pass by default. Search the target company's careers page plus relevant domestic platforms such as BOSS直聘, 猎聘, 智联招聘, 前程无忧, 拉勾, 牛客, 实习僧, 应届生求职网, 国聘, and the National College Student Employment Service Platform when relevant. Read [references/web-research.md](references/web-research.md). Treat platform availability, duplicates, stale postings, login walls, and search snippets as research limitations, not as candidate evidence.
- When the user asks for company or employer recommendations, enter `company_recommendation` mode in addition to or instead of resume generation. Read [references/company-recommendation.md](references/company-recommendation.md). Use the user's desired employment city/region to select the market route: mainland China uses Chinese domestic sources, overseas cities use local-language/international sources, and Hong Kong/Macau/Taiwan are labeled as a separate regional route. Default to 20 distinct companies; honor an explicit count, never pad with duplicates, and explain any shortfall. Every recommendation must include a matching role or an explicit `potential_fit` label, city, match reasons tied to resume evidence IDs, gaps, public source URLs, source type, and retrieval date.
- Always produce exactly three visual styles from the same compiled text: `ats` (conservative single-column), `modern` (restrained accent and compact sidebar), and `research` (academic/technical hierarchy). For each style, deliver an editable DOCX and a PDF; HTML previews are optional. Style differences may change typography, spacing, color, and visual grouping, but may not change, add, remove, or reorder factual resume text.
- Treat layout as a first-class constraint. Read [references/layout-and-assets.md](references/layout-and-assets.md) whenever producing or reviewing a visual resume. `modern` and `research` must use a genuine narrow-left/wide-right two-column body; `ats` may remain single-column for parser safety. Enforce visible size hierarchy for name, headline, section headings, entry headings, dates, and body text.
- Preserve user-supplied avatar, photo, QR code, portfolio QR, and similar images unless the user explicitly asks to remove them. Embed them in every final DOCX/PDF style, keep their aspect ratio, and place them in the header's right visual block. Use `images.avatar` and `images.qr_code` when available, with compatibility aliases described in [references/layout-and-assets.md](references/layout-and-assets.md). If an asset is missing or unsupported, record the omission in `audit.assets` and continue without inventing a replacement.

## Workflow

1. Inventory every supplied file and prompt. Use `scripts/inventory_sources.py` when a folder contains multiple sources. For PDF or DOCX files, use the matching document/PDF capability when available and inspect layout as well as extracted text. Identify user-supplied images during inventory and retain their paths/bytes in the working manifest.
2. Perform the non-blocking intake pass. Ask once for missing essentials and high-value details using [references/required-information.md](references/required-information.md); continue with available facts even when the user does not answer.
3. Build an evidence ledger. Give each fact an ID, source location, date, confidence, allowed wording, and any conflicts. Read [references/evidence-ledger.md](references/evidence-ledger.md).
4. Parse the JD into a role-demand matrix: hard requirements, preferred skills, likely outcomes, keywords, seniority, domain language, and screening risks. Read [references/jd-rolefit.md](references/jd-rolefit.md).
5. Search current role-specific hiring signals and template conventions. Read [references/web-research.md](references/web-research.md). Select the market route from the role language, location, company, and user intent; for China-market roles include domestic platform sources. Record source URLs, retrieval date, role/market scope, platform limitations, and which decision each source changed.
6. If company recommendations were requested, normalize desired city/region and read [references/company-recommendation.md](references/company-recommendation.md). Run the matching domestic, regional, or international source route, collect current public role signals, deduplicate by normalized company name/domain, rank the default 20 companies by evidence-backed fit, and record the result in `audit.company_recommendations`. Do not claim a company is hiring unless a current or recent public signal supports it.
7. Score evidence against the role and, when applicable, each recommended employer. Mark every demand as `proven`, `adjacent`, `unknown`, or `absent`; use the score to prioritize content and recommendations, never as a promise of interview probability.
8. Compile the content: target headline, short summary, skills, education, experience, and projects. Each factual bullet must map to one or more evidence IDs in the working manifest. Use the bullet shape `action + method + context/scope + sourced result or artifact`.
9. Choose the smallest useful set of role variants, but always render all three visual styles for the selected role variant. Reorder projects and skills by the JD; do not duplicate a full resume for trivial keyword changes. Visual style changes must not change the text. Make role-variant differences, recommendation route, and style differences explicit in the audit report.
10. Render all three HTML previews from [assets/resume_template.html](assets/resume_template.html) with `scripts/build_resume_html.py --all-styles`, then create `resume-ats.docx`, `resume-modern.docx`, and `resume-research.docx` with `scripts/build_resume_docx.py --all-styles`. Confirm that `modern` and `research` contain real two-column tables, that all headings have intentional size hierarchy, and that supplied images are embedded. Export one PDF for each corresponding DOCX while preserving the same compiled content. Prefer the host's document/PDF capability for rendering and visual inspection; use `scripts/convert_docx_to_pdf.py` when a DOCX-to-PDF converter is available.
11. If the user uploads an edited DOCX and asks for PDF, enter `edited_docx_to_pdf` mode. Use the edited DOCX itself as the conversion source, preserve its text and layout, do not rebuild it from the old manifest, and return a PDF with the matching base name. If the upload is merely a source resume for tailoring, treat it as candidate material instead and do not convert it automatically.
12. Validate before delivery. Run `scripts/validate_resume_package.py` against the compiled manifest, evidence ledger, research record, company recommendation record when requested, all three HTML files, all three editable DOCX files, and all three PDFs when present. Re-render the PDFs and visually inspect every page if the host supports it. Fix missing columns, missing images, weak heading hierarchy, overflow, clipped text, broken glyphs, missing sections, or excessive whitespace before delivery.

## Minimal human gates

Do not pause solely because a field is missing. Ask the grouped intake questions once and continue with a partial draft or structure-only draft when necessary. Pause only for a material contradiction, a safety-sensitive ambiguity, or genuinely incompatible target roles; even then, produce the safe portion that can be supported by the available evidence. Record every unresolved field in `audit.intake`, `needs_confirmation`, or `excluded_claims`.

## Outputs

For a normal resume run, deliver exactly three same-text style packages, each containing an editable DOCX and a PDF, plus optional HTML previews and a compact audit report containing target role, domestic or international web research route, web research sources/signals, platform limitations, evidence coverage, intake status, missing-information checklist, assumptions, excluded claims, style comparison, generation mode, and validation results. When company recommendations are requested, also deliver a deduplicated list of 20 companies by default (or the user's requested count), grouped or labeled by desired city, with matching role, fit explanation, evidence IDs, gaps, public links, source types, retrieval dates, and limitations. For edited DOCX conversion, deliver the corresponding PDF and a conversion audit noting the source DOCX and that the DOCX itself was preserved. Keep the audit report separate from the resume. Do not expose private source text unnecessarily.

For a GPT configured in ChatGPT, place the behavior in Instructions and upload the focused reference files/template as Knowledge; enable Code Interpreter & Data Analysis when generated files or the included scripts are needed. In Codex, this folder is a directly loadable Skill package. External job-board or ATS integrations require an explicitly configured action or app and are outside this Skill's default scope.
