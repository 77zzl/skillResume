# 排版与用户图片约束

## 目标

简历不是把文字自动堆到页面上，而是从同一份编译文本生成结构稳定、层级清晰、适合人工阅读和必要 ATS 解析的版式。排版变化只能改变视觉呈现，不能改变事实、文字、顺序或证据。

## 固定版式规则

- 页面默认 A4 纵向、单页；内容过多时先压缩冗余和间距，不通过极小字号或隐藏内容强行塞入一页。
- 页眉必须形成三级层级：姓名为最大字号，职业标题/目标方向为次级字号，联系方式为辅助字号。姓名、标题、联系方式不能挤成同一字号。
- `modern` 和 `research` 必须使用真实的双栏主体：左栏放目标方向、核心能力和教育经历，右栏放个人概览、工作经历和项目经历；左栏与右栏顶部对齐，并用细分隔线或留白建立层次。
- `ats` 可以保留单栏作为投递安全版本，但必须保留清晰的标题字号层级，并使用与双栏版本相同的正文、标题、条目顺序和事实文本。
- 左栏宽度约占正文区域 30%–36%，右栏约占 64%–70%；正文两侧留白一致，不能出现只剩窄缝的右栏。
- 一级区块标题应使用明显大于正文的字号、加粗、主题色和底部短线/色块/留白中的至少两种信号；条目标题大于条目元信息，日期和地点使用辅助色。
- 工作/项目条目必须避免跨栏拆开；条目标题应与紧随其后的职责或成果保持在一起。
- 排版不能使用图片承载简历文字、技能条、评分图表或关键关键词。双栏只改变布局，正文仍然必须是可复制、可搜索的普通文字。

## 头像与二维码

- 用户提供的头像、证件照、微信二维码、作品集二维码等图片属于候选人材料。只要用户未明确要求删除，就必须保留到所有最终视觉风格中，包括可编辑 DOCX 和由 DOCX 导出的 PDF。
- 默认位置为页眉右侧：头像保持原始宽高比，二维码置于头像旁或下方，二维码下可显示用户提供的标签（没有标签时可使用“微信联系”这一中性标签）。
- 不擅自替换、重绘、过度裁剪、加滤镜或改变图片内容；只允许在不失真的前提下缩放和留白。
- 图片必须作为 DOCX 的真实嵌入图片写入 OOXML 包，而不是仅在 HTML 中引用本地路径。HTML 预览应优先将本地图片转为 data URI，避免换机器后图片丢失。
- 图片缺失、格式不支持或路径不可访问时，记录在 `audit.assets` 和交付说明中，但仍继续生成文字简历；不得用占位框、随机图片或虚构图片替代。
- 不把个人头像或二维码上传到招聘网站、外部搜索查询或第三方服务；联网搜索只使用岗位、城市和公开招聘信号。

## Manifest 图片字段

优先使用以下结构；为兼容旧输入，也可读取顶层 `avatar`、`photo`、`qr_code`、`wechat_qr` 或 `qr`：

```json
{
  "images": {
    "avatar": {"path": "C:/path/avatar.jpg", "alt": "候选人头像"},
    "qr_code": {"path": "C:/path/wechat-qr.png", "alt": "微信二维码", "label": "微信联系"}
  }
}
```

`path` 可以是本地文件路径，图片也可以直接使用 `data:image/...;base64,...`。生成器应优先支持 PNG、JPG/JPEG 和 GIF；遇到不支持的格式应明确披露，而不是静默丢弃。

## 三种风格的区别

| 风格 | 主体布局 | 视觉重点 | 使用场景 |
| --- | --- | --- | --- |
| `ats` | 单栏 | 标准标题、稳健字号、少装饰 | 网申系统、无法确定解析器的招聘门户 |
| `modern` | 左窄右宽双栏 | 青绿色、头像/二维码页眉、信息分组和紧凑留白 | 人工阅读、中文社招和综合岗位 |
| `research` | 左窄右宽双栏 | 深蓝色、学术/技术层级、方法和项目条目 | 技术、科研、研究生和作品导向岗位 |

三种风格必须从同一 manifest 渲染。切换风格时只允许改变字体、字号、颜色、边框、间距、栏宽和视觉分组，不得改变简历事实或增删文字。

## 视觉 QA

生成后逐个检查三种 HTML、三种 DOCX 和三种 PDF：

1. 头像和二维码是否存在、清晰、比例正确且没有被裁掉；
2. 姓名、职业标题、区块标题、条目标题、日期的字号是否有明显层级；
3. `modern` 和 `research` 是否确实为双栏，左栏和右栏内容是否按规则分布；
4. 是否出现跨栏断裂、重叠、溢出、孤立标题、空白页或过密正文；
5. Word 文本是否可编辑，PDF 文本是否可复制，三种风格文字是否一致；
6. 图片和排版问题是否记录在审计，而不是用静默降级掩盖。
